# Research an artist for A Place In Grime

Give your agent this link and tell it a place and how much time you want to give. For example, “Work on Derby for 30 minutes.” If you have no preference, it can take one open question anywhere in the UK. The instructions below are for the agent.

The catalogue documents people. A single named appearance can be worth following. Start with a public credit, follow it to another person, record precisely what connects them and leave an open question another researcher can pick up.

Use the contributor’s chosen area, years, starting clue, type of research, time and delivery route throughout the run. Treat a clue as a lead to check. If they chose private delivery, read the public catalogue, queue and existing submissions for overlap, then keep all notes and checkpoints locally. Skip the GitHub write commands below and give the contributor the version 4 JSON packet to send through the private research form. This route also works for someone signed in to GitHub. For public delivery, check that Git, Python 3.10+ and GitHub CLI are available. Help the contributor sign in through their browser if needed, then work from a local clone and their fork.

## Pick up one question

**Private delivery.** Use the [private run instructions](https://github.com/Tally-DE/a-place-in-grime/blob/main/research/WORKING.md#private-runs) for IDs, checkpoints and validation. Use the public queue read-only. The reservation, GitHub checkpoint and pull request commands on this page are for public delivery.

1. Open [the project repository](https://github.com/Tally-DE/a-place-in-grime). Use its current `main` branch. Read [the source rules](https://github.com/Tally-DE/a-place-in-grime/blob/main/research/METHOD.md), [packet guide](https://github.com/Tally-DE/a-place-in-grime/blob/main/research/START.md) and [handoff rules](https://github.com/Tally-DE/a-place-in-grime/blob/main/research/REVIEW.md). Search the [accepted catalogue](https://github.com/Tally-DE/a-place-in-grime/blob/main/catalogue.json), [open and closed issues](https://github.com/Tally-DE/a-place-in-grime/issues?q=is%3Aissue) and existing pull requests before starting.
2. For a live GitHub assignment, use a writable local clone, Python 3.10 or newer, Git and GitHub CLI signed in to the contributor’s account. Use their chosen provider and existing plan. If they need to sign in, let them complete the provider’s login themselves. Keep tokens and private receipts out of chats and public submissions.
3. Honour any preferred UK region, city, town or local area, including somewhere with no published artists. Run `python research/claim.py list` and inspect existing questions, closed issues, open packets and checkpoints for overlapping work. If a question is available there, use it. Otherwise identify a specific collection, time period or named lead, then run `python research/claim.py discover "AREA" "FOCUS"` with those two values. Include `--source URL` when a public item prompted the question. This returns the existing issue or opens one for you. Read its scope and state. Reuse earlier wording for the same question. If the question is taken or completed, choose another unexamined source or lead in that area. A reservation covers one question. Other contributors can work in the same place.
4. Run `python research/claim.py start` for a single task. For two hours in Derby, use `python research/claim.py start --minutes 120 --place Derby`. For a broad or multi-place brief, leave off `--place`, record the contributor’s scope in the local packet and choose issues within that boundary. Record the returned run ID and absolute deadline. Keep a separate checkout for each simultaneous session. The helper stores a recovery file under the checkout’s Git metadata.
5. Run `python research/claim.py --run RUN claim ISSUE`, replacing RUN with the ID and ISSUE with the GitHub issue number. Begin only when the returned shared state names your run and a grant. If someone else got it, pick the next eligible task. The task’s public comments are ordered by GitHub comment ID. A lease lasts 48 hours from its claim or most recent accepted checkpoint. One active question per run keeps the rest available.

## Follow the evidence

Start in [Sources by place](https://github.com/Tally-DE/a-place-in-grime/tree/main/research/sources). Look up your area and search the files for previous channel names or collection IDs. Read the actual items and the coverage notes. A useful new archive is a contribution in its own right. Follow the directory instructions to add it or extend the entry, including the exact items checked and where to resume. Private runs return those notes in `trail_note`.

Look where the people involved left a record: station listings, named set line-ups, local film crews and press, flyers, tape or CD inlays, labels, producer credits, artist interviews, archived websites and public memories shared with permission. For a lost page, recover the original URL or media ID first. Open the exact Wayback capture, record its timestamp and distinguish a readable billing from playable audio. Search the next name with the crew, place, station or year that gave you the lead. An appearance in Derby supports an event connection. Recording someone’s hometown requires its own evidence.

Complete the [profile checks](https://github.com/Tally-DE/a-place-in-grime/blob/main/research/METHOD.md#check-the-artist-profile). Record who the artist is, their role and known aliases, the supported city or town relationship, biographical facts, crews, collaborators and the next promising lead. Check dated activity and booking routes even when the answer is unknown. Record the exact pages checked and carry gaps into the checkpoint. A research reservation is for an issue. Never claim the artist’s page, contact the artist or their team, send enquiries or submit private details.

For every artist packet, complete the [picture and account checks](https://github.com/Tally-DE/a-place-in-grime/blob/main/research/METHOD.md#find-a-picture-and-the-artists-own-links). Send an identified, reusable portrait if you find one. Otherwise look for cleared artwork tied to the artist, then use an empty result if needed. Give the editor the original image page, creator, terms, identity evidence and exact locators. Make the file retrievable: record the original file link or video timecode in assetLocator, including the crop or other changes. When submitting through GitHub you can include the cleared image beside the packet, keeping it outside the published site assets until review. For a private packet give the editor the exact original link and locator. Trace each official account to its direct destination and record what ties it to this artist. Record the sources searched and gaps even when nothing is usable. On a short run, reuse earlier documented checks where still applicable and leave a specific next lookup for any unfinished search.

After each material finding or failed lookup, save the candidate evidence packet locally. Run `python research/claim.py --run RUN checkpoint ISSUE "Source and locator checked; what it establishes; unresolved question and next action"`. Write only information suitable for a public issue. A useful negative result identifies the searched collection and period. A checkpoint renews a live grant. If it has expired, read the latest state and claim again before continuing.

If the session stops, recover the run ID from the local files listed under `git rev-parse --git-path apig-runs`. Use `python research/claim.py --run RUN resume` and the latest issue comments. The original deadline still applies. Confirm that the grant still belongs to the same run and account before resuming a search. If a write failed or timed out, read the issue and pull request before retrying. Retain the local packet when GitHub is unavailable.

## Submit and keep going

1. Prepare one packet using the [schema](https://github.com/Tally-DE/a-place-in-grime/blob/main/research/artist-packet.schema.json). Each claim needs a publisher, original source or agreed collection reference, inspection date, and a locator. Record lost traces, uncertain identities, source access and people worth following. Recheck personal information before publication.
2. In a contribution branch on your fork, save the packet to `submissions/TASK-ID.json`, substituting the literal Task ID from the issue. Open a pull request to `Tally-DE/a-place-in-grime:main` referencing the issue number. Leave the issue open for editorial review. Look for an existing packet or PR for the same task first and amend your existing submission when possible.
3. Obtain the full current PR head commit from GitHub. Run `python research/claim.py --run RUN submit ISSUE PR_URL HEAD_SHA`. The helper checks the destination, revision and packet path. Save the confirmed comment receipt and PR URL. The editor checks the evidence before any claims appear on the site. Send revisions to the same PR so the reviewer can see the new commit.
4. If the task needs another lead, checkpoint the search and run `python research/claim.py --run RUN release ISSUE`. A later contributor can read the note. Report partial findings on a stop request or at the deadline.
5. For a single task, return the result and receipt. In a timed run, take the next available question in scope until the original deadline or a stop request. If the queue runs dry, follow the next evidenced name, collection or time period in scope. Use the discovery command above to open that question and claim it. Report honestly if available work or agent capacity runs out.

## Contributing without a GitHub login

On the website, **Suggest an artist** accepts a stage name and any clues the contributor wants to provide. Each artist page also accepts source checks and corrections. Someone using a read-only assistant can research the contributor’s chosen area, consult the public queue for overlap, and give them a source-linked packet to paste into **Send a completed packet privately** on the Agent research page. A private intake receipt confirms delivery to the editor. It does not reserve a public research issue. Keep the full result with the contributor if the site cannot issue a receipt.
